## 代码结构

`index.html` 是单文件应用，按以下顺序组织：

```
├── <style>          CSS 变量定义 + 全局样式 + 组件样式
├── <div id="app">   主容器（JS 动态渲染）
├── <div id="modal-root">   编辑弹窗容器
├── <div id="toast-root">   Toast 提示容器
└── <script>
    ├── 常量定义         CATEGORIES, STORAGE_KEY, 阈值等
    ├── 工具函数         uid, fmtTime, fmtDuration, debounce 等
    ├── 本地存储         loadLocal, saveLocal, loadState, saveState
    ├── 同步模块         getSyncUrl, pullFromCloud, pushToCloud, debouncedPush
    ├── 数据管理         data, activePlan, activeRecord 等全局状态
    ├── 计划逻辑         startPlan, stopPlan, cleanupExpiredPlans
    ├── 记录逻辑         startRecord, endRecord, 计时器, 消遣提醒
    ├── 提醒音效         playChime (消遣 E5+G5), playPlanChime (计划 C-E-G)
    ├── 编辑/删除        editSession, updateSession, deleteSession
    ├── 查询函数         getTodaySessions, getTodayStats
    ├── 渲染函数         renderAll, renderApp, renderModal
    ├── 统计渲染         在 renderApp 中内联
    ├── 设置页渲染       在 renderApp 中内联
    ├── 导出/导入        exportData, importData
    ├── Toast            showToast
    └── 初始化           init, 事件监听, 定时器
```

### 渲染机制

整个页面采用**全量重渲染**模式：每次状态变更调用 `renderAll()`，完全重建 DOM。简单直接，适合这个规模的应用。性能无需担心——单页数据量极小。

### 状态变量

| 变量 | 类型 | 说明 |
|---|---|---|
| `data` | `{ sessions: [] }` | 所有会话数据（计划 + 记录） |
| `activePlan` | object \| null | 当前活跃的计划 session |
| `activeRecord` | object \| null | 当前活跃的记录 session |
| `recordStartTime` | number \| null | 记录开始的时间戳（毫秒），用于计算已过时间 |
| `currentMode` | `"plan"` \| `"record"` | 当前模式 |
| `currentTab` | `"timeline"` \| `"stats"` \| `"settings"` | 当前标签页 |
| `editingSession` | object \| null | 正在编辑的 session |
| `alertTriggered` | `{ [id]: true }` | 已触发过消遣提醒的 session id |
| `planAlertedIds` | `Set` | 已触发计划到期提醒的 session id（防重复） |

## 常见开发任务

### 新增一个分类

1. 在 `PLAN_CATEGORIES` 中添加条目
2. 在 `RECORD_CATEGORIES` 中添加对应条目（如果要区分的话）
3. 在 CSS `:root` 中添加对应的颜色变量
4. 在 CSS 中添加 `.cat-btn.{key}.active` 样式规则
5. 如果是计划专用，确认不需要加入 `RECORD_CATEGORIES`

### 修改消遣提醒阈值

改常量 `ENTERTAINMENT_ALERT_MIN`（第 ~25 行附近），单位分钟。

### 修改计划时长

改常量 `PLAN_DURATION_MIN`，单位分钟。

### 添加新的统计维度

统计逻辑在 `renderApp()` 函数的统计标签页部分。数据计算在 `getTodayStats()` 中。添加新维度时：
1. 在 `getTodayStats()` 中计算新数据
2. 在统计标签页渲染中输出新 UI

### 添加导出/导入支持新格式

修改 `exportData()` 和 `importData()` 函数。注意 `importData` 按 `id` 去重合并。

### 修改 UI 样式

所有 CSS 在文件顶部的 `<style>` 标签中。使用 CSS 变量（`--work`, `--text` 等）控制颜色体系。

## 部署流程

### 部署到 GitHub Pages

通过 Cola 对话部署，或手动执行：

```bash
# 需要 GitHub token（~/.cola/deploy/github_token）
GH_TOKEN=$(cat ~/.cola/deploy/github_token)
GH_USER="vivianta"

# 1. 上传文件为 blob
CONTENT_B64=$(base64 -i index.html)
INDEX_SHA=$(curl -s -X POST "https://api.github.com/repos/$GH_USER/cola-pages/git/blobs" \
  -H "Authorization: Bearer $GH_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -d "{\"content\":\"$CONTENT_B64\",\"encoding\":\"base64\"}" | python3 -c "import sys,json; print(json.load(sys.stdin)['sha'])")

# 2. 获取当前 gh-pages tree SHA
PARENT_SHA=$(curl -s "https://api.github.com/repos/$GH_USER/cola-pages/git/ref/heads/gh-pages" \
  -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github+json" | python3 -c "import sys,json; print(json.load(sys.stdin)['object']['sha'])")
BASE_TREE_SHA=$(curl -s "https://api.github.com/repos/$GH_USER/cola-pages/git/commits/$PARENT_SHA" \
  -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github+json" | python3 -c "import sys,json; print(json.load(sys.stdin)['tree']['sha'])")

# 3. 创建 tree
TREE_SHA=$(curl -s -X POST "https://api.github.com/repos/$GH_USER/cola-pages/git/trees" \
  -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -d "{\"base_tree\":\"$BASE_TREE_SHA\",\"tree\":[{\"path\":\"time-awareness/index.html\",\"mode\":\"100644\",\"type\":\"blob\",\"sha\":\"$INDEX_SHA\"}]}" | python3 -c "import sys,json; print(json.load(sys.stdin)['sha'])")

# 4. 创建 commit
COMMIT_SHA=$(curl -s -X POST "https://api.github.com/repos/$GH_USER/cola-pages/git/commits" \
  -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -d "{\"message\":\"Deploy update\",\"tree\":\"$TREE_SHA\",\"parents\":[\"$PARENT_SHA\"]}" | python3 -c "import sys,json; print(json.load(sys.stdin)['sha'])")

# 5. 更新 gh-pages 引用
curl -s -X PATCH "https://api.github.com/repos/$GH_USER/cola-pages/git/refs/heads/gh-pages" \
  -H "Authorization: Bearer $GH_TOKEN" -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -d "{\"sha\":\"$COMMIT_SHA\",\"force\":false}"

# 6. 等待构建（约 30-60 秒），然后访问
echo "https://vivianta.github.io/cola-pages/time-awareness/"
```

## 注意事项

### 不要做的事

- **不要在 `index.html` 中引入外部依赖** — 保持单文件自包含
- **不要修改 localStorage key 名称** — 会导致用户数据丢失
- **不要更改 sessions 数据结构** — 与云端 Sheets 中已有数据不兼容。如需变更，需写迁移逻辑
- **不要删除 `cola-pages` 仓库中非 `time-awareness/` 的文件** — 可能有其他 Cola 部署的页面
- **不要用 `force: true` 推送 gh-pages** — 会覆盖其他人的部署

### 数据迁移

如果必须修改 sessions 数据结构，在 `init()` 的数据完整性检查部分添加迁移代码：

```javascript
// 在 init() 中，renderAll() 之前
for (const s of data.sessions) {
  if (!s.newField) s.newField = defaultValue;  // 补新字段
}
saveLocal(data);
```

### 同步冲突

两个设备同时修改数据时，后推送的覆盖先推送的。对个人使用场景可接受。
如需改善，可在 session 上添加 `updatedAt` 字段，合并时保留较新的值。
