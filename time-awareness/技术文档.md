## 数据架构

### 数据模型

所有数据为单个 JSON 对象，存储在：
- **本地**：`localStorage` key `timeperception_v2_data`
- **云端**：Google Sheets 的 A1 单元格（整个 JSON 作为字符串）

```json
{
  "sessions": [
    {
      "id": "lnk9x...",
      "type": "plan",
      "category": "work",
      "start": "2026-07-31T07:23:00.000Z",
      "end": "2026-07-31T08:23:00.000Z"
    },
    {
      "id": "lnka2...",
      "type": "record",
      "category": "entertainment",
      "start": "2026-07-31T08:30:00.000Z",
      "end": null
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识（时间戳 36 进制 + 随机串） |
| type | `"plan"` \| `"record"` | 条目类型 |
| category | string | 分类 key（见下方分类表） |
| start | ISO 8601 string | 开始时间 |
| end | ISO 8601 string \| null | 结束时间，null 表示进行中 |

### 活跃状态

`activePlan` 和 `activeRecord`（进行中的计划/记录）不存储在 sessions 数据中，而是单独保存在 `localStorage` key `timeperception_v2_state`。跨设备同步时，从 sessions 数据推导：

- **活跃记录**：`type === "record"` 且 `end === null` 且 `start` 为今天
- **活跃计划**：`type === "plan"` 且 `end > 当前时间` 且 `start` 为今天（取最新一条）

### 分类定义

```javascript
// 计划模式（5 个）
const PLAN_CATEGORIES = {
  work:          { name: '工作/学习', icon: '💼', color: '#4A90D9' },
  chores:        { name: '家务',      icon: '🏠', color: '#4CAF84' },
  exercise:      { name: '锻炼',      icon: '🏃', color: '#F09B4A' },
  recharge:      { name: '充电',      icon: '🔋', color: '#8B7EC8' },
  entertainment: { name: '消遣',      icon: '📱', color: '#E0687A' },

// 记录模式（6 个，多一个"未记录"）

```

## 同步机制

### 数据流

```
设备 A 修改数据
  → 保存到 localStorage（即时）
  → debouncedPush（3 秒防抖）
  → fetch POST → Apps Script → Sheets A1 单元格

设备 B 打开页面
  → 读取 localStorage（缓存，即时渲染）
  → fetch GET → Apps Script → Sheets A1 单元格
  → merge（云端数据 + 本地独有的条目）
  → restoreActiveFromData（推导活跃计划/记录）
  → 重新渲染
```

### 推送触发时机

1. 每次数据变更后（3 秒防抖）
2. 页面关闭/刷新时（`beforeunload` → `sendBeacon`）
3. 页面切到后台时（`visibilitychange` → `sendBeacon`）
4. 用户手动点击「立即同步」

### 合并策略

- 云端数据和本地数据按 `id` 去重合并
- 本地独有的条目保留（不会被云端覆盖）
- 冲突处理：后写入覆盖先写入（无版本号，个人使用场景可接受）

## 部署

### GitHub Pages 部署

通过 GitHub API 直接操作 `vivianta/cola-pages` 仓库的 `gh-pages` 分支：

1. 创建 blob（上传文件内容）
2. 创建 tree（基于现有 tree + 新 blob）
3. 创建 commit（挂到 tree 上）
4. 更新 gh-pages 引用（非强制推送）
5. GitHub Pages 自动构建

每次部署覆盖 `time-awareness/` 目录，不影响同仓库其他页面。

### Apps Script 部署

1. 打开 Google Sheets → 扩展程序 → Apps Script
2. 粘贴 `sync-backend.gs` 全部代码
3. 部署 → 新部署 → 网页应用
4. 执行身份：我，访问权限：任何人
5. 复制 Web 应用 URL，粘贴到设置页

## 关键常量

| 常量 | 值 | 说明 |
|---|---|---|
| `PLAN_DURATION_MIN` | 60 | 计划固定时长（分钟） |
| `ENTERTAINMENT_ALERT_MIN` | 20 | 消遣提醒触发阈值（分钟） |
| `SYNC_DEBOUNCE_MS` | 3000 | 推送防抖间隔（毫秒） |
| `STORAGE_KEY` | `timeperception_v2_data` | localStorage 数据键 |
| `STATE_KEY` | `timeperception_v2_state` | localStorage 状态键 |

## 开发与修改

1. 编辑 `~/cola/outputs/时间知觉/index.html`
2. 本地测试：`python3 -m http.server 8080` → `http://localhost:8080`

3. 重新部署为网页应用（生成新 URL）
4. 更新设置页中的同步 URL
